# プロバイダと設定

[English](Providers.md)

キーはすべてリポジトリ直下の `.env` に書きます (`.env.example` 参照)。キーはサーバーにだけ置かれます。サーバーは起動時に使うプロバイダを選び、`GET /api/config` とロビー下部に有効なものを表示します。Anthropic のキーがない場合、サーバーは **モックモード** で動きます。言語モデルの代わりにスクリプトの応答器を、検索の代わりにデモ用の出典を使うので、処理全体 (ルーティング、受け入れ判定、表示タイミング、段階的な層、論点マップ、こっそり解説) はそのまま動きます。

## 音声認識

| 役割 | プロバイダ                                               | 理由                                                                                                                                                                                               |
| ---- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 既定 | **Soniox** (`stt-rt-v5`)                                 | 日本語と英語を 1 つのモデルで扱い、同じストリーム内の言語切り替えに対応します。全トークンに言語ラベルが付き、リアルタイムの話者分離と発話区切りの検出があります。ストリーム 1 時間あたり約 $0.12。 |
| 予備 | **AssemblyAI** Universal Streaming (`universal-3-6-pro`) | 日本語対応、言語切り替え、ストリーミングでの話者ラベル、途中結果は約 150 ms。約 $0.45/時 + 話者ラベル。                                                                                            |

どちらも生の WebSocket で使います (`Apps/Server/Src/Speech`)。音声は 16 kHz・モノラル・PCM16 で、40 ms ごとのフレームで送ります。用語集の語と呼びかけ語は、語彙のヒントとして音声認識に渡します。

既定にしなかったもの: Google Chirp、OpenAI、ElevenLabs のリアルタイム版 (リアルタイムの話者分離がない)、Azure (連続言語識別が文の途中で言語を切り替えられない)、Speechmatics (日英のバイリンガルモデルがない)。

これらのサービスについて、日本語の文字誤り率を独立に比べたベンチマークはありません。ベンダーの数値は英語のものです。頼る前に、自分たちの日英混在の録音で評価してください。手順は調査メモにあります。

## 言語モデル

| 役割     | 既定                                                                                                                                                  | 設定                                                                          | 用途                                                                    |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| ルーター | Cerebras `gpt-oss-120b` (または Groq `openai/gpt-oss-20b`)。450 ms で Claude Haiku 5.5 に**ヘッジ**。高速ホストのキーがなければ Claude Haiku 5.5 のみ | 厳密な JSON スキーマ、低い推論努力                                            | ライブの発言から何を調べるかの判断 (きっかけの検出)、明示的な依頼の解釈 |
| 執筆     | `claude-haiku-5-5`                                                                                                                                    | 構造化出力、ストリーミング、思考なし、effort `low`                            | 一言、詳細、こっそり解説と聞き逃しの要約、匿名の懸念の書き直し          |
| 深い処理 | `claude-opus-5-5`                                                                                                                                     | 構造化出力、ストリーミング、effort `medium`、サーバー側の拒否時フォールバック | 論点マップと要約、深掘り調査の計画と執筆                                |

遅延を縮める工夫:

- **ルーターのヘッジ:** 最速のホストが答え、遅いか失敗したら Claude が引き継ぎます。gpt-oss の会議音声に対する日本語の精度が未検証であることも、ヘッジを使う理由です。
- **投機的ルーティング:** 話し途中の字幕が 30 文字伸びるたびに解析するので、話者が言い終わる前にカードが出ることもよくあります。
- **部分 JSON のストリーミング:** 一言が少しずつ表示されます。
- **プロンプトキャッシュ:** システムプロンプトはバイト単位で固定です。文字起こしは 20 発言ずつの固定チャンクにし、最後の完成チャンクにキャッシュの区切りを置くので、繰り返しの呼び出しはキャッシュ済みの前半を再利用します。
- **優先度:** 明示的な依頼は自発的な調査より先に処理されます。ホバーでの先読みは空きがあるときだけ動きます。

モデルは `MODEL_WRITER`・`MODEL_DEEP` で、ルーターは `ROUTER_PROVIDER` (`auto`、`anthropic`、`cerebras`、`groq`) と `ROUTER_HEDGE` で変えられます。

## 検索

| プロバイダ        | 種類                | キー                                                 |
| ----------------- | ------------------- | ---------------------------------------------------- |
| Parallel Search   | Web                 | `PARALLEL_API_KEY`                                   |
| Exa               | Web                 | `EXA_API_KEY`                                        |
| OpenAlex          | 論文 (英語・日本語) | 無料。`OPENALEX_API_KEY` / `OPENALEX_EMAIL` は任意   |
| Semantic Scholar  | 論文                | `SEMANTIC_SCHOLAR_API_KEY` (1 秒 1 リクエストに制限) |
| Wikipedia (ja/en) | 百科事典            | 無料                                                 |

調査の深さ:

| 深さ     | 検索                                                                    | 期限   | 執筆                          |
| -------- | ----------------------------------------------------------------------- | ------ | ----------------------------- |
| さっと   | Web を競わせて最初の有用な結果を採用。補足カードでは Wikipedia も       | 1.8 秒 | 一言のみ (詳細は求められたら) |
| 標準     | 日英のクエリを Web に並列で投げ、論文または百科事典も加える             | 2.8 秒 | 一言 + 詳細                   |
| じっくり | 深いモデルがサブクエリを 3〜5 個計画し、徹底的な Web 検索と論文を加える | 9 秒   | 一言 + 詳細 + 深掘りの節      |

自発的なカードはルームの既定の深さ (設定 → ルーム) を使います。明示的な依頼は、コマンドバーで選んだ深さか、「ざっと」「詳しく」などの言い方から推定した深さを使います。

## 会議との連携

- **Zoom RTMS:** `ZOOM_CLIENT_ID`、`ZOOM_CLIENT_SECRET`、`ZOOM_WEBHOOK_SECRET_TOKEN`、`PUBLIC_BASE_URL`。
- **会議ボット (Recall.ai、実験的):** `RECALL_API_KEY`、`RECALL_API_BASE_URL`、`MEETING_BOT_NAME`、`PUBLIC_BASE_URL` (HTTPS で外部から到達できること)。
- **Google Meet アドオン:** `VITE_MEET_CLOUD_PROJECT_NUMBER`。

設定方法は [MeetingPlatforms.ja.md](MeetingPlatforms.ja.md) を参照してください。
